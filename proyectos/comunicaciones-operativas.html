Automatización de comunicaciones operativas

Diseño y desarrollo de una herramienta interna para centralizar y automatizar el envío de comunicaciones operativas recurrentes mediante plantillas y scripts integrados con Outlook.

Antes ~5 min
Después ~1 min
Reducción ~80%

Contexto

Dentro de la operación existían comunicaciones que debían enviarse de manera recurrente, con estructuras similares y dependiendo de la frecuencia o situación operativa.

Estas comunicaciones podían ser diarias, semanales o mensuales y requerían preparar manualmente el contenido del correo antes de enviarlo.

Para facilitar esta actividad, desarrollé una herramienta que centraliza diferentes plantillas y automatizaciones dentro de una única interfaz.

El problema

La preparación individual de los correos generaba trabajo repetitivo, especialmente cuando se trataba de comunicaciones recurrentes con estructuras similares.

El proceso manual también implicaba buscar la plantilla correspondiente, copiar información, preparar el mensaje y configurar los elementos necesarios antes del envío.

Repetitividad

Preparación frecuente de comunicaciones con estructuras similares.

Tiempo

Aproximadamente 5 minutos para preparar una comunicación.

Consistencia

Riesgo de utilizar estructuras diferentes o modificar incorrectamente una plantilla.

Accesibilidad

Necesidad de localizar manualmente la plantilla o estructura correspondiente.

El reto Centralizar las comunicaciones recurrentes y reducir el tiempo necesario para preparar los correos.

La solución

Diseñé y desarrollé una pequeña aplicación basada en HTA que funciona como un punto central de acceso a diferentes scripts y plantillas de comunicación.

La herramienta reúne aproximadamente 20–30 tipos de comunicaciones utilizadas con diferentes frecuencias dentro de la operación.

Dependiendo del tipo de comunicación, la herramienta puede generar el correo listo para revisión o ejecutar directamente el envío cuando el flujo lo permite.

01 Seleccionar
02 Preparar
03 Validar
04 Enviar

Cómo funciona

01 · Selección

El usuario selecciona desde la interfaz la comunicación que necesita realizar.

02 · Preparación

El sistema utiliza la plantilla y lógica correspondiente para construir el correo.

03 · Validación

Las comunicaciones que requieren información adicional pueden ser revisadas o modificadas antes del envío.

04 · Envío

El correo se genera y, según el tipo de comunicación, queda listo para envío o se ejecuta automáticamente.

Arquitectura de la solución

La herramienta integra diferentes tecnologías para proporcionar una interfaz sencilla y centralizar la lógica de las comunicaciones.

HTA

Interfaz utilizada para centralizar las diferentes opciones de comunicación.

HTML / CSS

Construcción y presentación de la interfaz de la aplicación.

JavaScript

Lógica de interacción y control de las diferentes funcionalidades.

VBS

Automatización de tareas y ejecución de acciones relacionadas con el entorno operativo.

Outlook

Integración utilizada para generar y gestionar las comunicaciones.

Tipos de comunicaciones

La herramienta centraliza aproximadamente 20–30 comunicaciones y plantillas utilizadas en diferentes momentos de la operación.

Diarias

Comunicaciones asociadas a actividades recurrentes de la operación.

Semanales

Mensajes utilizados para seguimiento y actividades periódicas.

Mensuales

Comunicaciones asociadas a procesos de cierre o actividades periódicas.

Casos específicos

Plantillas utilizadas cuando se requiere una comunicación particular dentro del proceso.

Impacto

La herramienta redujo el tiempo aproximado de preparación de una comunicación de 5 minutos a cerca de 1 minuto, dependiendo del tipo de mensaje.

5 min → 1 min Reducción aproximada del 80% en el tiempo de preparación de las comunicaciones automatizadas.

Eficiencia

Menor tiempo dedicado a preparar comunicaciones recurrentes.

Estandarización

Centralización de plantillas y estructuras de comunicación.

Accesibilidad

Acceso centralizado a las diferentes comunicaciones desde una única herramienta.

Reutilización

Capacidad de reutilizar la misma estructura para diferentes comunicaciones y frecuencias.

Mi participación

Identifiqué la oportunidad de centralizar y automatizar comunicaciones recurrentes que requerían trabajo manual dentro de la operación.

Diseñé y desarrollé la estructura de la herramienta, integrando la interfaz, las plantillas y los scripts necesarios para automatizar las diferentes comunicaciones.

También realicé pruebas, ajustes y validaciones para asegurar que las diferentes opciones funcionaran correctamente dentro del flujo operativo.

Análisis

Identificación de comunicaciones repetitivas y oportunidades de automatización.

Diseño

Definición de la estructura de la herramienta y organización de las diferentes plantillas.

Desarrollo

Construcción de la interfaz e integración de scripts y funcionalidades.

Validación

Pruebas, correcciones y adaptación de la herramienta al funcionamiento operativo.

Resultado

La solución permitió centralizar diferentes comunicaciones operativas dentro de una única herramienta, reduciendo el tiempo de preparación y disminuyendo la dependencia de tareas manuales repetitivas.

Además, la centralización facilitó el acceso a las diferentes plantillas y contribuyó a mantener una estructura más uniforme en las comunicaciones recurrentes.

Confidencialidad

Por tratarse de una herramienta desarrollada dentro de un entorno corporativo, la versión pública del proyecto no expone correos reales, destinatarios, información de clientes, plantillas corporativas ni scripts internos.

La descripción presentada utiliza una estructura conceptual para explicar el funcionamiento y el impacto de la solución sin revelar información sensible.
